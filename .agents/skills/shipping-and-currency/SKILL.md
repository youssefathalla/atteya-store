## Shipping and prices outside Egypt

- **Shipping**: `settings/shipping` (public read, admin write) holds the Egypt boxes and the international boxes (one to three each, `box1`/`box2`/`box3`, each with max weight, L×W×H cm, and `feeEgp`), plus free-over, a scheduled promo, and a note. Zone fees, `baseFee`, and flat `internationalShippingFeeEgp` are removed (admin save deletes legacy fields; seed and checkout fall back to placeholder box rates until saved). Each region has one to three boxes (`box1`…`box3`; Egypt uses two: up to 1 kg = 115 EGP, up to 3 kg = 135 EGP, client rates Nov 2026). Customers never choose a box. `planDelivery()` (engine `shipping.ts`, shared by checkout and `priceStoreOrder`) weighs the bag with `parcelWeight()` and `assignShippingBox` picks the smallest box that fits. `shippingQuote` then takes the cheapest of the box fee, the Settings → Shipping promo, free-over, and live Free shipping offers (`reward.kind: 'freeShipping'`, minimum counted after item offers); Free shipping offers apply to Egypt orders only, so an order shipped abroad always pays its international box fee unless a Settings → Shipping rule makes it cheaper (tests in `shipping.spec.ts`). The storefront says the same: `offerTitleVisible(offer, visitorCountry)` (`@core/services/offers/offer-shop`, an unknown country counts as Egypt) keeps a Free shipping offer's title off the product page's offer lines and out of Shop's `?offer=` heading for a visitor outside Egypt; that Shop page still lists the offer's products, under the normal Shop title and with no subtitle (tested by `npm run test:cart`). `weightGrams` 0 is a real weight (socks never add to the parcel); a product with no weight counts as `ASSUMED_WEIGHT_GRAMS` (500 g) per unit, a last resort because every category has a default. Egypt orders heavier than every box are **delivery fee to be agreed**: the order is placed (InstaPay or Cash on Delivery only; Card is hidden and refused) with shipping line `kind: 'domestic-agreed'`, `priceEgp: 0`, `feeAgreed: false`, and `totalEgp` = items only. `orderStage()` returns `fee-to-be-agreed` (`isDeliveryFeeToBeAgreed()`), so no InstaPay box or payment request shows until staff agree the fee on WhatsApp and save it with the admin `setDeliveryFee` callable (Orders → Set Delivery Fee, changeable while open). That sets the shipping line, `feeAgreed: true`, `totalEgp`/`totalDisplay`, `deliveryFeeSetAt`/`deliveryFeeSetBy`, and sends the `delivery-fee-set` email the first time and `delivery-fee-changed` on each later change (claimed per save in `orderEmails/{orderId}_delivery-fee-changed_{deliveryFeeSetAt ms}`); `confirmCodOrder` refuses until then. Promotions and free shipping don't apply to these orders. Abroad heavier than every box can't be ordered. Product weights: staff type one per product (product form, Weight (g)), or use **Products → Catalogue Tools → Shipping Weights** (admin callable `productWeights`: `preview`, `saveDefaults`, `fillEmpty`). That window edits each category's default (`categories/{id}.defaultWeightGrams`: grams, `null` = no default on purpose, missing = built-in), lists products with no weight (links to each), and Fill Empty Weights gives every product without a weight its default; a weight already set is never replaced. `defaultWeightGrams(categoryIds, name, saved)` in `catalog-taxonomy.ts` (both copies) resolves leaf, then parents, then the built-in `DEFAULT_WEIGHT_GRAMS_BY_CATEGORY` (client figures: t-shirts 250, shorts 250, hoodies 800, socks 0; our estimates until the client confirms: tracksuits 700, rackets 400, bags 900, balls 250, grips 50, bottles 200, supports 100, sets and bundles 500); any "jacket" by name is 800 g. The product form prefills the same default on create. Firestore can't query a missing field, so the "no weight" list lives in that window, not as a Products table filter. The server ignores any box on the client payload, prices with `shippingQuote`, and stores `boxId` plus `domestic-box` or `international-box` on the order. Checkout shows Subtotal, Shipping, and Total in the visitor's display currency. Edited in Settings → Shipping with an Egypt / Abroad region toggle; the storefront shows it as the shipping slide of `app-announcement-bar` (“from” = lowest Egypt box fee). `shippingSettingsResolver` on the main layout seeds `settings/shipping` through TransferState (`shipping-settings`) on SSR so Egypt first HTML includes the bar when currency is EGP. When the visitor's currency is not EGP, `bannerText` and `shippingLine` are empty. While `html[data-cur-pending]` is set, the announcement bar's shipping slide is `display: none` (and the whole bar when that is its only slide), so a foreign visitor does not see the EGP message before hydration and the bar does not reserve space for it. Egypt never sets that attribute, so the banner stays.
- **Outside Egypt prices**: `intlPricing/config` (markup percent, default 40, admin-only read) and `intlPricing/rates` (raw EGP rates, admin-only read) are written only by Cloud Functions. `settings/currency` is public read and functions-only write. It stores one combined `factor` per currency (`(1 + markup/100) * rate`) for every finite rate above 0 that open.er-api.com returns, except EGP. It has no markup field and no per-currency step. `refreshExchangeRates` (daily 04:00 Africa/Cairo, `open.er-api.com`) keeps the previous rate for any code that moved more than 50% on a scheduled run, and still saves the rest. A manual refresh accepts the jump and returns warnings. `setInternationalPricing` and `refreshExchangeRatesNow` are admin callables. There is no currency switcher and no saved choice. **Visitor location** comes from CDN/platform geo headers when present (App Hosting does not pass them today), then a short IP lookup (`ipwho.is`) from `X-Forwarded-For` (`visitor-geo.ts`, `/api/visitor-location` for client-rendered routes). Express resolves geo once per HTML request, sets `x-atteya-visitor-country` on the incoming request (stripping any client-sent value first), and `serverCurrencyResolver` runs `CurrencyService.prepareForServerRender()` during SSR navigation (not `APP_INITIALIZER`, so `REQUEST` is available). Geo-priced storefront HTML (`/`, `product/**`, `category/**`, `brand/**`, `search`) uses `Cache-Control: private, no-store` so App Hosting CDN never caches visitor-specific prices. ISO country maps to display currency via CLDR (`scripts/generate-tz-currency.mjs` → `country-currency.ts`; functions copy `functions/src/intl/country-currency.generated.ts` + `currencyFromCountry()`). Egypt (`EG`) and a visitor whose country can't be found (the `ipwho.is` lookup failed, logged as `Visitor country lookup failed`) get EGP; a country with no currency in the map or with one of `UNRELIABLE_CURRENCIES` (`LBP`, `SYP`, `YER`, `SDG`, `VES`, `ZWL`, `IRR`) uses USD. Non-production builds default unresolved geo (typical localhost/private IP) to `EG` / EGP via `applyDevLocalGeoFallback()` in `visitor-geo.ts`. Boot seeds transfer through `TransferState`. `?cur=` overrides one visit and is stripped, never stored. Prices round up in `toDisplayAmount` to a 1/2/5 step near 1.5% of the amount (whole units, or 3 decimals for `KWD`, `BHD`, `OMR`, and `JOD`). A foreign browser converts in `app-product-price` (`toDisplayAmount` + `formatMoney`). The Firestore read sits behind `import('./currency-loader')`. `OrderPricingSnapshot` (`src/app/core/services/orders/order-pricing.model.ts`) is the field contract: shipping country decides the order, and shipping stays a separate line with no product markup. International and Egypt shipping boxes live under Settings → Shipping (AS-46).
- **Price factors in one transaction (<KEY>-233)**: `setInternationalPricing` (writes `intlPricing/config`, `settings/currency` and the audit log) and `refreshRates()` (writes `intlPricing/rates` and `settings/currency`) in `functions/src/intl/` read `intlPricing/rates` and `intlPricing/config` in the same `db.runTransaction` as their writes, so a markup save and a rate refresh at the same moment never mix inputs; the provider fetch stays outside the transaction, and a fetch older than the saved `providerUpdatedAt` only stamps `lastAttemptAt`, so it never rolls rates back.
