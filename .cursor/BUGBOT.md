# Review rules for Atteya Store

Cursor Bugbot reads this file on every pull request. The Claude review workflow (`.github/workflows/claude-review.yml`) reads it too, and agents use it for their own review before opening a PR. `AGENTS.md` is the full contract; this is the short list of things that break production, money, data or security here. Flag a change that breaks one of these. Don't flag style, naming or "consider adding tests".

## Money and prices

- Prices are whole Egyptian pounds. Offer prices are **never** written into product docs; they come from the shared engine (`functions/src/offers/engine/`). The browser copy in `src/app/core/services/offers/engine/` is generated by `npm run sync:engine`: an edit to the browser copy only, or copies that differ, is a bug.
- Checkout must re-price on the server from Firestore (`createCodOrder`, `createInstapayOrder`, `createPaymobOrder`). Trusting a price, total, shipping box or fee sent by the client is a bug.
- Paymob: `amount_cents = totalEgp * 100`, currency is always EGP. `paymobWebhook` must verify HMAC-SHA512, confirm only when the signed amount equals `paymob.amountCents` and the currency is exactly `EGP`, and stay idempotent (`paymobWebhookEvents`).
- Shipping is priced by `planDelivery()` / `shippingQuote` from `settings/shipping` boxes. `weightGrams` 0 is a real weight, not "missing".
- What an order shows or says (InstaPay box, WhatsApp text, emails) comes only from `orderStage()` / `paymentDue()` on the saved order.

## Stock

- `stock`, `stockBySize` and `inStock` are written together, only through `stockFields()` / `bootstrapStock()` in `functions/src/products/stock.ts`. `inStock` is always `stock > 0`; `stock` equals the sum of `stockBySize` when sizes exist.
- No client code writes product docs or stock fields. Admin stock edits go through the `setProductStock` callable in a transaction.
- Stock is taken on confirm (`confirmCodOrder`, `paymobWebhook`), never on order creation.

## Security and access

- Admin is the Firebase Auth custom claim `role: 'admin'` and nothing else. Granting admin from Firestore data or a client write is a bug. Rules and callables also honour `roles/{uid}.revokeTimeMs`.
- Admin callables must check the caller (`requireRole`) before doing anything. Callables must validate every input field.
- A public product, category or brand query must include `where('published', '==', true)`.
- Clients must not be able to write `orders`, `orderRateLimits`, `paymobWebhookEvents`, `roles`, `auditLogs`, `orderEmails`, product docs, or `settings/currency`. Check `firebase/firestore.rules` and `firebase/storage.rules` changes against `AGENTS.md`.
- `importImageFromUrl` limits (https on 443, at most 3 checked redirects, 10 s, 10 MB, magic-byte check) must not be loosened.
- Never commit secrets: Paymob keys, Resend key, Algolia admin/write key, service accounts, `.env` files.
- GitHub Actions: no untrusted PR text in `run:` scripts, no `pull_request_target` with a checkout of PR code, the smallest token permissions.
- Regexes on user input must not backtrack badly (ReDoS).

## Firestore and data

- Validate external data with Valibot (`v.parse` / `v.safeParse`, `createValibotConverter()` for Firestore) before use.
- List queries need `limit(n)`; counts use `getCountFromServer()`. A new query that needs an index must add it to `firebase/firestore.indexes.json` in the same PR.
- `set(..., { merge: true })` with dotted keys like `categories.<id>` stores a literal field name. Use nested objects.
- Files kept identical in two places must stay identical: `catalog-taxonomy.ts`, the shared part of `search-tokens.ts`, `order-ref.ts` / `order-email-model.ts` (`shortOrderRef`), `store-info.ts`, `order-messages.ts` (the last two via `npm run sync:engine`).

## SSR and performance

- Geo-priced HTML (`/`, `product/**`, `category/**`, `brand/**`, `search`) must send `Cache-Control: private, no-store`. A public cache header on these leaks one visitor's prices to another.
- No browser-only APIs (`window`, `document`, `localStorage`, GSAP) during server rendering; use `afterNextRender` or a platform check. Server data reaches the browser through `TransferState`, not a second read that makes the page flicker.
- Above-the-fold and LCP content is not deferred; only slide 0 of the hero has `priority`.

## Angular and UI rules that cause real defects

- Signals and `resource()` / `rxResource()`. No manual `isLoading` / `error` signals with try/catch, no Zone APIs (`fakeAsync`, `tick`), no `@Input` / `@Output`, no `*ngIf` / `*ngFor`.
- Media uses `NgOptimizedImage` (`[ngSrc]`) with `[appImageFallback]`, and URLs only from `@shared/utils/image` helpers. A raw `<img [src]>` for media is a bug.
- No Tailwind classes on Angular Material components. No `text-on-surface`. Corner radius is `border-shape`, never `rounded-*`.
- Buttons with a loading state show only the spinner, with an `aria-label` while loading. No clickable `div` or `span`: use a `button` or a link.
- User-facing text: buttons and payment or status names in title case ("Place Order", "Cash on Delivery", "Waiting for Payment"); sentences, hints and snackbars in sentence case; plain words, no developer jargon.

## How to report

Say what breaks, for whom, and how to reproduce it. High = production money, data, security or a broken checkout. Medium = a real bug users or staff will hit. Low = a real but minor defect.
