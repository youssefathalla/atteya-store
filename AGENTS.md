# 🤖 AI Agent Master Guide

This repository contains a production-grade **Angular v22+ (Zoneless, Signal-First)** application with **Tailwind CSS v4** and **Angular Material M3**.
Adhere strictly to these core directives to ensure maximum performance, clean architecture, and seamless collaboration.

---

## 🧠 1. Core Architectural Directives

### 🅰️ Angular & Signals (Strict Modern Standards)

- **Signal-First Reactivity**: Use `signal()`, `computed()`, and `effect()`. Zero Zone.js dependencies (`fakeAsync`, `tick` are forbidden).
- **Resource-First Data Fetching (v22+)**: Use `resource()` (Promises) and `rxResource()` (Observables/streams). Manual loading/error states (`isLoading = signal(false)`, manual `try/catch`, `error = signal(...)`) are forbidden.
- **Inputs & Outputs**: Use `input()` / `input.required()` and `output()`. No legacy `@Input` or `@Output`.
- **Control Flow**: Modern template syntax only (`@if`, `@for`, `@let`, `@switch`). No `*ngIf` or `*ngFor`.
- **Template Access**: Templates can read `private` component members; avoid redundant `protected` visibility.
- **Defaults in v22+**: Standalone (`standalone: true`), `OnPush`, and Zoneless are defaults in v22+. Do not write redundant flags or `provideZonelessChangeDetection()`.
- **HTTP Configuration**: `HttpClient` is provided in root by default. `provideHttpClient(...)` is optional and only needed when registering interceptors (`withInterceptors`), XSRF protection, or `withXhr()`. FetchBackend is the default engine (`withFetch()` is deprecated).
- **Services**: Use `@Service()` from `@angular/core` instead of legacy `@Injectable({ providedIn: 'root' })`.
- **Forms**: Prefer Signal Forms for modern state management.
- **Deep Reference**: Activate the **`angular-developer`** skill and review `.agents/skills/angular-developer/references/angular-version-matrix.md`.

### 🧭 Routing & Route Data

`withComponentInputBinding()` is **enabled** in `app.config.ts`, so route state flows into components as signals — no `ActivatedRoute` plumbing.

- **Router Resources (v22.2+)**: Route-level data fetching uses `resources: (ctx) => ({ ... })` with `nonBlocking(...)` instead of legacy resolvers. The resolved or streaming resource binds directly to component `input.required<Resource<T>>()`.
- **Throwing Redirects**: Throw `new RedirectCommand(router.parseUrl(...))` directly inside guards and resource loaders rather than returning UrlTrees.
- **Route data is an `input()`**: path params, matrix params, query params, static `data`, and resource output all bind to matching input names (`readonly id = input.required<string>();`).
- **Precedence on duplicate keys** (lowest to highest): query params -> path/matrix params -> static route `data` -> resource/resolver data.
- **`ActivatedRoute` is the exception**: reach for it only inside guards or when parent/child route state is needed. Never inject it just to read route params.
- **Lazy by default**: prefer `loadComponent` / `loadChildren` for feature routes.

### 🎨 Design System & Styling

- **The Contract**: Token vocabulary and hard bans live in `.cursor/rules/design-system.mdc` (Cursor auto-loads for `.html`, `.css`, `.scss`, and `.ts`) and `.agents/rules/design-system.md` (Antigravity glob rule). Edit the **body** in `.cursor/rules/design-system.mdc`, then run `npm run sync:agents` so Antigravity stays aligned. Adhere to all semantic tokens, M3 overrides, `<mat-icon name="icon" />` with `SharedIconModule`, and utility extraction rules.
- **Zero Tailwind on Angular Material**: Angular Material components (`button[matButton]`, `button[matIconButton]`, `<mat-icon>`, `<mat-menu>`, `<mat-drawer>`, etc.) are already fully styled by the M3 theme. **NEVER** apply Tailwind styling, color, transition, or hover classes to Material components. Only style **native HTML elements** (`<div>`, `<nav>`, `<section>`, `<ul>`, `<a>`, etc.) unless explicitly instructed by the user.
- **Monochrome (Black & White) Identity**: Brand aesthetic is strictly Black & White. `primary` is black; default text is naturally `text-on-surface` (inherited from `body`). **NEVER write `text-on-surface` on any element** — it is already the default inherited color and writing it is banned as redundant class bloat. Never add redundant child color overrides (e.g. `<span class="text-primary">.</span>`), and inherit colors cleanly.
- **Layout Alignment Shortcuts**: Always use custom layout shortcuts instead of writing verbose flex classes: Row: `elements-center`, `elements-start`, `elements-end`, `elements-between`. Column: `elements-center-col`, `elements-start-col`, `elements-end-col`, `elements-between-col`.
- **United Border Shape (`border-shape`)**: Single source of truth for corner radius across all elements is `border-shape` (`border-radius: var(--border-shape, 2px)`). Arbitrary `rounded`, `rounded-corner-xs`, `rounded-sm`, `rounded-md`, `rounded-lg` are strictly banned.
- **Button Loading State Standard**: During action loading (`isSaving()`, `isUploading()`, etc.), render **only the spinner** (`<mat-progress-spinner mode="indeterminate" diameter="18" />`). Never display text alongside a spinner. Swap the label/icon cleanly with `@if (isLoading()) { <mat-progress-spinner ... /> } @else { <mat-icon ... /> <span>Label</span> }` and provide `[attr.aria-label]="isLoading() ? 'Action...' : null"` for screen readers.
- **United Button Icon Sizing**: All `<mat-icon>` placed inside buttons (`matButton`, `matIconButton`, or native `<button>`) automatically default to `DEFAULT_BUTTON_ICON_SIZE` (`'lg'`) via `MatIconDirective` and `.mat-mdc-button-base mat-icon`. Never write `size="..."` on any icon inside a button.
- **Universal Plain-Language Microcopy**: All user- and admin-facing copy (buttons, dialogs, snackbars, alerts, hints, empty states) must speak the natural, everyday language of general users. Always communicate user intent and real-world outcomes rather than technical mechanisms, developer jargon, or underlying systems. Keep action labels simple, familiar, and active, and ensure all feedback is constructive, reassuring, and intuitive.
- **The Reference**: Activate the **`design-system`** skill for the styling directory map, token registration, Material overrides, and component APIs.

### 📐 Layout & Viewport Sizing Standards

1. **Top-Level Query Container**:
   - `<main>` inside `main.component.html` carries `@container`. Page-level sections and cards must use `cqw` to remain fluid relative to drawer open/close and responsive main layouts.
   - Never place `@container` on the same element where `cqw` padding is declared (CSS cannot query itself).
2. **Angular Component Host Sizing**:
   - All section and page components (`app-*-section`, `app-*`) must define `host: { class: 'block w-full' }` in `@Component()` to prevent `display: inline` height/width collapse.
3. **Full-Viewport Sections**:
   - Full-screen heroes directly below the header must use `h-[calc(100dvh-56px)]` (accounting for the 56px / `h-14` navbar).
   - When a full-height hero is specified, do NOT add `aspect-*` (`aspect-video`, `aspect-21/9`) to the slide containers, as `aspect-ratio` overrides height in modern CSS.
4. **Section Spacing**:
   - Use `.container-content` as the single unified class for page section layout and responsive container padding (`p-[5cqw]`). Do not append `.section-space` to elements that already have `.container-content`.

### 🛡️ Data Validation (active) & Firebase (target state)

- **Strict Validation — ACTIVE**: `valibot` is installed and in use (`src/app/shared/schemas/`, `src/app/shared/ui/status-badge/status.model.ts`). Pipe all external data through a schema (`v.parse()` / `v.safeParse()`) before use. Use `createValibotConverter()` for Firestore documents. See the **`typescript`** skill for the schema rules.

> [!IMPORTANT]
> **Native Firebase JS SDK (`firebase`) is standard.** Do NOT install or use `@angular/fire`. Native Firebase SDK functions (`getDoc`, `signInWithEmailAndPassword`, `onSnapshot`) are framework-agnostic, take explicit instances, and do NOT require an Angular injection context or `runInContext()` wrappers. Storage and Functions are not registered at startup. `injectStorageAsync()` and `injectFunctionsAsync()` (`@core/firebase`, region `europe-west3`) return a loader. Call them from an injection context, store the function, and invoke it on each use. A successful SDK load is reused. A failed chunk load is dropped so the next call retries.

- **Admin access**: Firebase Auth custom claim `role: 'admin'` is the source of truth. Anything else, or a missing claim, is a normal user. Rules and callables check `token.role == 'admin'` only. Do not grant admin through Firestore data or a client write. `roles/{uid}` is a mirror index written only by the Admin SDK (`functions/scripts/set-admin.mjs`, `listAdmins`, `setUserRole`). It may be missing for an admin granted outside the repo; `listAdmins` and `--list` read the claim. Removing an admin revokes that account's refresh tokens and writes `roles/{uid}.revokeTimeMs` (Auth `tokensValidAfterTime` in milliseconds). Rules reject an admin token whose `auth_time` is older than that value, and admin callables do the same check against Auth. A missing mirror, or a mirror without `revokeTimeMs`, does not block an admin. `auditLogs/{id}` is append-only from the Admin SDK. Clients, including admins, cannot write either collection. While a person is signed in, the app listens to their `roles/{uid}` doc and refreshes the ID token when that mirror role changes.
- **Sign-in**: `/login` (client-rendered) offers Google and email/password. There is no sign-up screen and no `createUserWithEmailAndPassword` call. Browser auth is `initializeAuth` with indexedDB then local persistence and no `popupRedirectResolver`, so `__/auth/iframe.js` and gapi are not loaded on ordinary pages. `signInWithPopup`, `signInWithRedirect`, and `getRedirectResult` pass `browserPopupRedirectResolver` explicitly. `getRedirectResult` runs only when `sessionStorage` key `atteya-auth-redirect` was set immediately before `signInWithRedirect`, or when the path is `/login`. The server still uses `getAuth()`. `AuthService` uses `onIdTokenChanged` plus `getIdTokenResult`. On the server the visitor is signed out (`user` null, `role` `'anon'`). `user` is published only after the role is known. Three roles: a visitor is signed out and can browse; a normal user is signed in without the admin claim, can browse and sign out, and cannot open `/admin/*`; an admin has `role: 'admin'` and a current session and can use `/admin/*`. `adminGuard` (also `canActivateChild`) sends a visitor to `/login?returnUrl=…` and a signed-in non-admin home with "This account can't manage the store." The first entry force-refreshes the ID token. The admin layout leaves the page if that person is demoted or signed out. The navbar account menu waits until auth is ready in the browser, then shows Sign in, or the person's name, Sign out, and Admin dashboard only when `isAdmin()`. The server renders that same waiting button so the prerendered page matches the first client render.
- **Storefront access**: `firebase/firestore.rules` allows anyone to read documents directly in `settings` (`settings/home`, `settings/navigation`, and any later sibling). Only an admin can write them. Subcollections under `settings` are denied. `roles/{uid}` is readable by that person or an admin, and `auditLogs` by an admin. Clients cannot write either. `products/{id}` is readable when `published == true`, or by an admin whose session is still current (`isAdmin()`, including `revokeTimeMs`). A public product query must include `where('published', '==', true)` or the rules reject it. Only that admin can create, update, or delete products. `settings/catalog` is a public settings document of published counts (`categories`, `types`, `brands`, `total`). While it is missing or still only an import lock, the storefront shows every navigation link. `importEasyOrdersProducts` (`europe-west3`, admin only, 540 seconds) copies the EasyOrders catalogue in batches. `EASYORDERS_CURRENCY_ID` and `EASYORDERS_ORIGIN` are public `defineString` params with defaults, also listed in `functions/.env.example`. Prices are whole Egyptian pounds. Format them with the `egpPrice` pipe. `penceToPounds` stays the legacy GBP pence pipe. Other collections are admin-only. `firebase/storage.rules` lets anyone get one object under `hero/`, `categories/`, `products/`, and `brands/`. Listing those folders is admin-only. Only an admin can upload a JPEG, PNG, WebP, or AVIF under 10 MB there, and `hero/default-hero.jpg` cannot be deleted. Every other path is denied. Storefront pages still load images through ImageKit and the public bucket URL. `importImageFromUrl`, `listAdmins`, `setUserRole`, `setProductStock`, `createProduct`, and `updateProduct` (`europe-west3`) require an admin caller. Image import accepts https on port 443 only, follows at most 3 redirects (each checked again), stops after 10 seconds, caps the body at 10 MB while streaming, and accepts only JPEG, PNG, WebP, or AVIF whose magic bytes match. `firebase.json` runs `npm --prefix functions run build` before a functions deploy. App Check is wired with `APP_CHECK_ENFORCED` defaulting to false until real reCAPTCHA Enterprise keys exist. There is no rules test suite in this repo.

- **Signals & Resources Integration**:
  - One-off reads (`getDoc`, `getDocs`): Feed directly into `resource()`.
  - Dynamic queries: Feed `onSnapshot` into `rxResource()`.
  - Static query listeners: Use `signalCollection()` or `signalDoc()`.
  - Updates automatically trigger zoneless change detection.
- **Query Efficiency**: Always apply `limit(n)` on list queries and use `getCountFromServer()` for counts.
- **Pagination**: cursor-based. `PaginationServiceInterface<T>` (`src/app/shared/ui/reusable-table/table.model.ts`) is implemented by `ProductsPaginationService`; with a pagination service, `ReusableTable` sorts on the server through `setQuery(where, sorts)` and `sort()`. Refresh re-reads the current page from its first doc (`startAt`).

- **LIFT Structure**: Feature modules live in `src/app/features/[feature-name]/`. Co-locate template and style files inside `<name>/<name>.component.*`. When a feature or page has dedicated services, utils, dialogs, or subcomponents, organize them in explicit subfolders (`services/`, `utils/`, `dialogs/`, `components/`) to eliminate root folder clutter. Do NOT generate or write `.spec.ts` test files.
- **SEO Metadata**: Inject and configure `SeoService` ONLY inside top-level Route/Page components in `ngOnInit()`.
- **Performance (@defer)**:
  - Below-the-fold content: `@defer (hydrate on viewport)`.
  - Completely static content: `@defer (hydrate never)`.
  - Above-the-fold / Hero / LCP content: Do NOT defer.

### 🖼️ Image Delivery & Optimization Architecture (ImageKit + Firebase Storage + Cloud Functions)

- **Proxy Architecture**: Master media files reside permanently in Firebase Cloud Storage. ImageKit acts as an external Web Folder origin (`https://storage.googleapis.com/<bucket>/`), intercepting requests to perform real-time resizing, WebP/AVIF compression, and global CDN delivery. That Google Cloud Storage URL is authorized by bucket IAM, not by `firebase/storage.rules`. Shop-category images are stored under `categories/` and follow the same path (`NgOptimizedImage` → ImageKit, then `buildStorageUrl()` on failure). Public `allow read` in storage rules only covers Firebase SDK and `firebasestorage.googleapis.com` reads (today, `/hero` only). Do not add public Storage-rule reads for `categories/`, `products/`, or `brands/` to unblock storefront images. EasyOrders photos are copied by the Admin SDK to `products/<docId>/<sha1 of the source URL>.<ext>` (`jpg`, `png`, `webp`, or `avif`). The path is a pure function of the URL, so a later import skips a file that is already there. DigitalOcean serves some JPEGs as `Content-Type: image/jpg`; `canonicalContentType()` in `functions/src/images/safe-image-fetch.ts` treats that as `image/jpeg` before the type and magic-byte checks.
- **Environment Isolation**:
  - **Dev (`environment.ts`)**: `https://ik.imagekit.io/atteyastore/dev/` fetching from `atteya-store-dev.firebasestorage.app`.
  - **Prod (`environment.prod.ts`)**: `https://ik.imagekit.io/atteyastore/` fetching from `attiya-store.firebasestorage.app`.
  - Dev uploads, previews, and tests never collide with or affect production assets or cache.
- **Angular Image & Fallback Standards**:
  - Provided via `provideImageKitLoader(environment.imageKitUrl)` in `app.config.ts`.
  - **Strictly use `NgOptimizedImage` (`[ngSrc]`) paired with `AppImageFallbackDirective` (`[appImageFallback]`)** for all storefront and preview media. Raw `<img [src]>` for media assets is banned.
  - `[appImageFallback]` automatically renders a monochrome `.skeleton` shimmer while loading and fails over once to `buildStorageUrl()` if ImageKit CDN fails or is still syncing.
  - Never build Storage or ImageKit URLs by hand; always use `normalizeImageKitPath()`, `buildImageKitUrl()`, and `buildStorageUrl()` from `@shared/utils/image`.
- **Media Uploads, Galleries & Validation**:
  - Use `ImageAssetSchema` / `ImageGallerySchema` (`@shared/schemas`) with required SEO alt text (max 125 chars) and raster formats only (JPG, PNG, WebP, AVIF — SVG is banned).
  - Use `<app-image-picker>` (`@shared/ui/image-picker`) for single images and `<app-image-gallery-editor>` (`@shared/ui/image-gallery-editor`) for multi-image galleries (max 8 images, index 0 = Main image, pre-generated ID folder `products/<productId>`).
  - Use `ImageSourceService` (`@core/services/storage`) for validating uploads, probing ImageKit via CORS-safe `new Image()`, and importing external https links via the `importImageFromUrl` Callable Cloud Function (`functions/`). The browser does not fetch that URL itself.
  - Track uncommitted session uploads per draft using `StorageAssetTracker` (`@core/services/storage`).
- **Skeleton Placeholders vs Blocking Spinners**:
  - Use `<app-skeleton>` (`@shared/ui/skeleton`) or `.skeleton` for layout/content placeholders (`@defer` placeholders, `resource.isLoading()` cards/lists/text) to prevent Cumulative Layout Shift (CLS).
  - Reserve `<mat-progress-spinner>` and `<app-loader>` for active button actions or blocking overlays.

## Learned Workspace Facts

- EasyOrders import: `markMissingProducts` sets `source.missingSince` and unpublishes SKUs missing from a run; when a product reappears with an unchanged catalogue hash, the `unchanged` touch must clear `missingSince` and restore `published` unless `published` is locked—not only `source.lastRunId`. On the final import slice, wrap `writeCatalogSummary(db)` in `try`/`finally` so `releaseImportRun(db)` always runs and the catalog lock cannot stick.
- Firestore `set` with `{ merge: true }` deep-merges nested map fields. Do not patch scoped `settings/catalog` counts with dotted top-level keys in `set()` (for example `categories.<id>`); Firestore stores literal field names and the real `categories`/`brands`/`types` maps stop updating.
- `/product/:slug` is server-rendered through a blocking resolver (`productPageResolver`) plus `TransferState`. A missing product gives a 404 via `RESPONSE_INIT` plus `noindex`; an out-of-stock product is 200 + `noindex` with everything disabled. The resolver also reads active public offers on the server (`PublicOffersReader`, no listener) and transfers them as `TransferOffer` (epoch-ms dates) with `renderedAtMs`; after hydration the PDP prices from the live `OffersService`. On the client, after that TransferState hand-off, the resolver reads the product through `ProductCacheService` (memory only, 60 seconds, 50 slugs, failures dropped). The server always calls `ProductService.getBySlug` and never fills the cache. `appPrefetchProduct` warms one slug after a 100 ms mouse rest or a mouse press, after a 100 ms keyboard rest, or after a still touch. Wheel and pointer-move listeners are passive. A wheel-scroll resets the rest and a moving touch is ignored, so scrolling or tabbing a grid does not read every card. Colour siblings `seed()` the docs `listModelGroup` already loaded. After hydration the product page listens to its own doc (`watchProductDoc` in `features/product/utils/product-live.ts`), so base price and stock replace any cached or prefetched values within about a second and stay live. Unpublished or deleted shows 'No longer available' and disables the options. `clear()` after admin saves is only a same-tab nicety.

### Catalogue, Search, Offers and Shipping (Step 1b)

- **Catalogue tree**: `categories/{id}` (two levels, `ancestorIds`, `path`) and `brands/{id}` are public-read when `published == true` (queries must include `where('published', '==', true)`). Products carry `categoryId`, `categoryIds` (leaf plus ancestors), `brandId`, `colors` (closed `ColorId` palette), `tags`, and derived `inStock`. `lockedFields` also accepts `colors` and `tags` (`inStock` is not lockable). Seeds and helpers live in `catalog-taxonomy.ts` (functions and Angular copies, keep identical). `migrateCatalogStructure` (admin callable, passes `add` and `dropLegacy`) seeds categories, brands and `settings/shipping`, and backfills products; `onProductCountsChange` keeps counts current.
- **Product stock**: `stock`, `stockBySize`, and `inStock` are always written together by `stockFields()` / `bootstrapStock()` in `functions/src/products/stock.ts`. `stock` is a whole number ≥ 0 and the source of truth; `inStock` is always `stock > 0`. `stockBySize` is only on products with a `size` option, keyed by that option's value ids, and `stock` equals the sum of the map (Firestore rules cannot sum a map, so `validStock` only checks the integer, `inStock`, and a map of at most 20 entries). Bootstrap runs only when `stock` is not yet a number and never overwrites an existing `stock`: untracked products (`trackStock === false`) get `untrackedDefaultStock()` on every size, or that default as flat `stock` when there is no size option (`currentProjectId()` in `functions/src/project-id.ts` reads `GCLOUD_PROJECT`, then `projectID.value()` from `FIREBASE_CONFIG`, because 2nd-gen functions often leave `GCLOUD_PROJECT` unset; `atteya-store-dev` → 10, any other resolved id including prod `attiya-store` → 0; an empty id throws instead of writing 0); tracked products with variants sum `variants[].stock` per size id (sizes with no rows are 0), or sum every variant when there is no size option; tracked products with no variants take EasyOrders' product quantity on import (whole number ≥ 0, missing = 0, and no map even when a size option exists) and the migration counts `stockNeedsImport` when that quantity is unknown. `hashCatalogueSlice` still hashes legacy `deriveInStock` (`trackStock` / `variants` / quantity), not `stock`. Search uses `stock > 0` when `stock` is a finite number, otherwise the stored boolean then `deriveInStock`, and does not index `stock` or `stockBySize`. The product page prefers `stock` / `stockBySize` and falls back to `trackStock` / `variants` until PR 1b. `ProductSchema` leaves `stock` and `stockBySize` optional with no default so a missing `stock` stays on that legacy path; a missing `inStock` still defaults to `true`. Do not run the catalogue migration or the import on prod until that 0 default is accepted — it would hide every untracked product from search and listings. Do not recompute `inStock` in a trigger that writes the product doc. Admin stock edits go through the `setProductStock` callable (a transaction on the live doc that merges the changed sizes, recomputes `stock`/`inStock` with `stockFields()`, and writes `updatedBy` (uid) and `updatedAt`). There is no client write of stock fields and no stock log yet. The product form (`createProduct` / `updateProduct`) writes stock only on create and when the sizes change: kept sizes keep their counts, new sizes take the starting count, removed sizes are dropped, all through `stockFields()`. A size sent without an id counts as new even when that id matches an existing size, so its starting count is saved. Adding sizes to a product that had none replaces that total with the per-size starting counts.
- **Product form**: `/admin/products/new` and `/admin/products/:productId` (`product-editor.page.ts`) save through the `createProduct` / `updateProduct` admin callables. There is no client product write any more. Dashboard products use a browser-generated Firestore auto-id, `source: null`, `trackStock: true`, `variants: []`, every lockable field locked, and `createdBy`/`updatedBy`. The slug is set once on create (unique, from the name when blank) and never changes. The description is plain text turned into `<p>` HTML on the server, and it's written only when it changed. Only the `size` option is editable, and other options are kept. Photos uploaded in a session and not kept are deleted. Photos removed from a saved product stay in Storage. The import never touches `source: null` products (`markMissingProducts` filters `source.system`, and import ids are `eo-…`). At delivery, import first, then add new products. Stock fields in the product form are text inputs checked by `isAllowedCount()`, with inline errors. The callables also reject bad counts; `stockFields()` clamping is only for the import. The description is turned into textarea text block by block (`plainFromHtml`), which round-trips with `descriptionToHtml`. A photo link to one of our own files outside the target folder is copied by `importImageFromUrl` (`path` input) into that folder. Width/height are the natural size, and the alt is the product name. Nothing deletes saved photos yet; any future cleanup must check every reference first, because older products and hero slides may share files.
- **Admin product search** uses Firestore `searchTokens` (not Algolia): `buildSearchTokens()` in `functions/src/products/search-tokens.ts` (Angular copy in `src/app/core/services/products/search-tokens.ts`, keep the shared part identical). Words go through `searchWords()` (NFD accent folding, lowercase English/Latin letters and digits). Tokens are each word plus its 2+ letter prefixes; a one-letter query word matches as a prefix in the client filter. After changing how tokens are built, run Catalogue tools → Check catalogue structure (Preview → Apply) on each project to rebuild them. Tokens are not in Algolia records.
- **Search (Algolia)**: `syncProductSearch` mirrors published products to the index; `reindexSearch` ("Rebuild search" in Catalogue tools) rewrites settings and records; failures land in `searchSyncErrors/{id}`. Indexes: `dev_products` / `prod_products` plus `_price_asc` / `_price_desc` replicas (sort on `displayPrice`). Dev and prod use separate Algolia applications (prod `EW50BE3MCR` / `attiya-store`). `ALGOLIA_WRITE_KEY` is a Secret Manager secret; never commit an Algolia Admin or Write key. The storefront uses the search-only key from `environment*.ts` through `SearchService` (lazy `algoliasearch/lite`, warmed when the search page is created in the browser). `/search` is server-rendered with `Cache-Control: private, no-store`: the heading, the query, and a skeleton grid are in the HTML, and a preconnect to `{appId}-dsn.algolia.net` is added from the search component. The results `resource` returns no params on the server, so it stays idle and hits never enter TransferState. The first two result images (one mobile row) use `priority`.
- **Offers**: `offers/{id}` is public-read only when `active == true && visibility == 'public'`; `offerCodes` is admin-only; `offerUsage` is Admin SDK only. **Never bake offer prices into product docs**: prices come from the shared pure engine in `functions/src/offers/engine/`, copied to `src/app/core/services/offers/engine/` by `npm run sync:engine` (`preflight` fails when the copies differ; edit only the `functions` copy). Algolia offer fields are display-only; checkout must re-price from Firestore. `onOfferWritten` and the 15-minute `refreshOfferPricing` schedule refresh them. Cart-level rewards show as labels until checkout exists.
- **Shipping**: `settings/shipping` (public read, admin write) holds base fee, zone fees, free-over threshold, a scheduled promo and a note. `shippingQuote` in the engine picks the lowest fee; the server stays authoritative. Edited in Settings → Shipping; the storefront shows `app-shipping-banner`. When the visitor's currency is not EGP, `bannerText` and `shippingLine` are empty. While `html[data-cur-pending]` is set, `app-shipping-banner` is `display: none`, so a foreign visitor does not see the EGP bar before hydration and the bar does not reserve space. Egypt never sets that attribute, so the banner stays. Domestic Egypt shipping does not apply abroad.
- **Outside Egypt prices**: `intlPricing/config` (markup percent, default 40, admin-only read) and `intlPricing/rates` (raw EGP rates, admin-only read) are written only by Cloud Functions. `settings/currency` is public read and functions-only write. It stores one combined `factor` per currency (`(1 + markup/100) * rate`) for every finite rate above 0 that open.er-api.com returns, except EGP. It has no markup field and no per-currency step. `refreshExchangeRates` (daily 04:00 Africa/Cairo, `open.er-api.com`) keeps the previous rate for any code that moved more than 50% on a scheduled run, and still saves the rest. A manual refresh accepts the jump and returns warnings. `setInternationalPricing` and `refreshExchangeRatesNow` are admin callables. There is no currency switcher and no saved choice. SSR stays on EGP. After hydration the browser maps the IANA timezone to a country and then a currency (`scripts/generate-tz-currency.mjs`, lazy `tz-currency.ts`). `Africa/Cairo` stays EGP and does not load that map. An unknown zone, a missing rate, or `UNRELIABLE_CURRENCIES` (`LBP`, `SYP`, `YER`, `SDG`, `VES`, `ZWL`, `IRR`) uses USD. `?cur=` overrides one visit and is stripped, never stored. Prices round up in `toDisplayAmount` to a 1/2/5 step near 1.5% of the amount (whole units, or 3 decimals for `KWD`, `BHD`, `OMR`, and `JOD`). A foreign browser converts in `app-product-price` (`toDisplayAmount` + `formatMoney`). The Firestore read sits behind `import('./currency-loader')`. Checkout is not built. `OrderPricingSnapshot` (`src/app/core/services/orders/order-pricing.model.ts`) is the field contract: shipping country decides the order, and shipping stays a separate line with no product markup.
- **Deploy**: the web app ships through App Hosting rollouts (GitHub-connected backend `atteya-store`; production sets `APP_HOSTING_ENV=prod` in `apphosting.production.yaml`). Default Firestore database `locationId` is `europe-west3` on both Firebase projects. `npm run fb:deploy:dev|prod` deploys Firestore, Storage and Functions only. `APP_CHECK_ENFORCED` is read at runtime by `requireAppCheck` inside `requireRole`.
- **Service worker** (`public/sw.js`, cache `atteya-store-v2`): cache-first only for hashed root build files (`name-XXXXXXXX.js|css`) and `/fonts/*.woff2`. It never caches HTML, `sw.js`, the manifest, icons or images. Activate deletes every other `atteya-store-*` cache, and the cache is capped at 200 entries. A changed font must get a **new file name** (fonts are cached forever). Bump `CACHE_NAME` only when the caching rules change. It's registered in `src/main.ts` outside dev mode only (`ng serve` unregisters it). `src/server.ts` serves `sw.js` as `no-store`, hashed files, fonts and `/media` as 1-year `immutable`, and other public files for 1 hour. Keep `HASHED_BUILD_FILE` identical in `sw.js` and `server.ts`.
- **Deploy safety**: every Firebase deploy runs through `scripts/deploy.mjs` via `npm run fb:*`, which runs the branch guard, the index check when indexes are included, a deploy summary, and (for prod) a typed `prod` confirmation. Use `npm run fb:deploy:dev|prod` for big features that change several of rules, indexes, storage, and functions at once; use the smaller `fb:indexes:*`, `fb:rules:*`, and `fb:fn:*` scripts for single-area changes. Read-only index reports: `npm run fb:indexes:check:dev|prod`. Do not use raw `firebase deploy`. Answer **N** to every Firebase delete prompt (indexes or functions) unless that exact deletion was agreed in the plan. Never pass `--force`. `firebase/firestore.indexes.json` is the single source of truth — add every new query index there in the same PR, never only via the console error link. **Agents never deploy**; Youssef deploys after merge.
- Functions deploy requires a gitignored `functions/.env` copied from `functions/.env.example` (the example file is not loaded); it supplies `defineString`/`defineBoolean` values at deploy time (`APP_CHECK_ENFORCED`, EasyOrders, `ALGOLIA_APP_ID`, etc.). A missing file or value may surface as a generic CLI error—use `firebase deploy --debug` to see the param name.
- First deploy of gen2 Firestore triggers on a Firebase project can fail while Eventarc service-agent IAM propagates (HTTP 400 on trigger creation); wait a few minutes and retry functions-only deploy (`npm run fb:fn:dev` or `fb:fn:prod`).

## Cursor Cloud specific instructions

- Node 22 matches `.nvmrc`. `package.json` pins `packageManager` to npm `11.17.0`. If `npm -v` is not that version, install it with corepack into the prefix that owns `npm` before `npm ci`. npm 11 warns that `@firebase/util` and `protobufjs` postinstall scripts are outside root `allowScripts`; the storefront and the functions tests still run.
- Install both lockfiles: `npm ci` at the repo root and `npm ci --prefix functions`.
- There is no Firebase emulator suite. The dev server reads live `atteya-store-dev`, ImageKit, and Algolia through the public client config in `src/environments/environment.ts`. Do not deploy.
- `security.allowedHosts` in `angular.json` is empty, so SSR rejects every Host header until `NG_ALLOWED_HOSTS=localhost,127.0.0.1` is set. Set `NG_CLI_ANALYTICS=false` so `ng serve` does not wait on the analytics prompt. Serve with `npm run dev -- --host 0.0.0.0 --port 4200`, and skip that launch when `http://localhost:4200/` already succeeds.
- Checks: `npm run preflight` (pricing-engine sync, design/a11y scan, eslint). The Angular app has no unit tests. In `functions/`, `npm test` compiles and runs the search-sync error tests. Development build: `npx ng build --configuration development`.
- Shopper check: home renders navigation from Firestore; `/search` queries Algolia; a result opens `/product/:slug` with an EGP price. Category and brand routes are placeholders and do not list products yet.
