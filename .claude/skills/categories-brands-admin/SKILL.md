# Categories and Brands Admin

## Categories & Brands page

- **Categories & Brands (admin, <KEY>-245)**: `/admin/categories` (sidebar **Categories & Brands**, `features/admin/pages/catalog-manager/`) has two tabs, Categories (a two-level tree) and Brands; it lists every doc, shown or hidden, with its live product count and Shown / Hidden (the address shows in the Edit window).
- **Not on the store yet (<KEY>-268)**: a shown row with no live products carries the muted tag "Not on the store yet: no live products" (`.catalog-row__tag`), because menus hide it and its address sends shoppers on; it goes once a product is live. A drag or Move Up / Move Down shows "New order saved." once `reorderCatalog` answers (both tabs), and the page says once under the title "Changes on this page save straight away."
- **Compact list (<KEY>-264)**: one short row per category (`app-catalog-row`, 56 px on phone, 52 px from `@3xl`): drag handle, an arrow only when it has categories inside, the name with "6 inside", "61 live" / "None live" (under the name on phone), a `mat-slide-toggle` Shown / Hidden switch and a ⋮ `mat-menu` (Edit, Add Inside on main categories, Move Up / Move Down, Open on the Store, Delete); addresses show only in the Edit window, hidden rows are greyed out.
- **Move Up / Move Down (<KEY>-265)**: the ⋮ menu moves a row one place within its own level (no Move Up on the first row, no Move Down on the last; `moveWithinLevel()` in `catalog-manager/utils/catalog-manager.utils.ts`), saved through `reorderCatalog` like a drag, so the order can be changed on a phone.
- Clicking a main category's name or arrow opens the categories inside it (indented, light grey, one level), ending with **+ Add to <name>** (Add Category with **Inside** set); which ones are open is held by the page (`openCategories`), so it stays while the page is open.
- The switch hides or shows at once (optimistic, put back on a failed save) with "Hoodies is hidden from the store." / "Hoodies is on the store."; hiding one with live products asks first (`hideConfirmMessage()`); the Brands tab uses the same rows and switch.
- A blocked Delete names what to do ("Apparel still has 58 live and 3 hidden products. Move them to another category first, or hide it instead.", "Delete or move the 6 categories inside Apparel first."; server `categoryDeleteBlockedReason()` / `brandDeleteBlockedReason()` in `functions/src/products/catalog-admin.ts`) in `app-delete-blocked-dialog` with **Hide Instead** (when shown) and, for a category with products, **See These Products** (opens `/admin/products?category=<id>`).
- Delete runs through `CatalogDeleteFlowService` (`catalog-manager/services/`, both tabs): `deleteCategory` / `deleteBrand` with `check: true` first (returns `blocked`, `offers` and `products`, deletes nothing), then the confirm window, which lists the offers that name it ("This offer will no longer include it: Summer Sale."), then the delete.
- After a delete the page takes its links out of `settings/navigation` (`CatalogAdminService.removeFromMenu()`, pure `removeFromMenu()` in `menu-placement.utils.ts`, saved with `NavService.updateNavigation()`): links whose target is it or whose address is its address, a menu name that opened it (the menu goes when nothing is left in it), and a "Sub-categories of" column for it (switched back to its own links); a failed menu save keeps the delete and says to remove the link in Navigation.
- Add Category shows Name (address under it), **Inside** (Nothing = a main category, or a main category; can't change later), **Show in the <menu> menu**, **Shown on the store** (on) and a closed **More Options** (native `details`: Size Chart, Details Title, Shipping weight, Name on Shop Tabs on main categories, Photo "Shown when someone shares this category's link."), whose closed line says "Same as Apparel", "Built-in settings" or the chosen values; there is no Description field (a saved description is sent back unchanged).
- Edit uses the same window (Inside shown as text) with **Delete** at the bottom; Delete closes it with `'delete'` and the tab runs the ⋮ Delete checks. Add Brand keeps Name, Logo, Show in the menu and Shown on the store, and Edit Brand has Delete too.
- Both windows open with `CATALOG_DIALOG_CONFIG` (`panelClass: 'catalog-dialog-pane'`, full screen below 640 px in `_dialog.scss`, buttons full width).
- A new category's or brand's id is its slug, made once from the name on the server (`newCatalogId()` in `functions/src/products/catalog-admin.ts`: accents folded, `a-z 0-9` joined by `-`, `-2` when taken; categories never take `all`, `shop`, `new`, `sale` or `best-sellers`); the slug and a category's parent never change afterwards.
- Every write goes through the admin callables `saveCategory`, `saveBrand`, `deleteCategory`, `deleteBrand` and `reorderCatalog` (`europe-west3`, `requireRole` staff, `functions/src/products/catalog-admin.fn.ts`, pure rules tested in `catalog-admin.test.ts`); each writes `updatedAt` / `updatedBy` (and `createdAt` / `createdBy` on add) and an `auditLogs` entry. No client write from that page; no rules change.
- Delete works for any category with no product (published or not) and no categories inside it, and any brand with no product, built-in ones (`SEED_CATEGORIES`, `SEED_BRANDS`) too (<KEY>-265); offers that name it (`offerNamesCatalogId()`) no longer block, they just stop including it. Every delete writes `auditLogs` (with `builtIn` and the offer names) and removes its `settings/catalog` count key.
- **Deleted built-ins (<KEY>-265)**: deleting a built-in adds its id to `settings/catalog.deletedBuiltInIds` in the delete's own transaction (category and brand ids never repeat, so one list holds both; written only by the callables, though the `settings/{docId}` rule lets staff write that doc).
- Check catalogue structure (`migrateCatalogStructure`) skips those built-ins and any built-in under a deleted parent (`seedsToKeep()`), never files a product without a category under a deleted one, and its preview lists them as "Deleted by staff" (`deletedByStaff` in the response).
- The store reads that list with the counts (`CatalogService.deletedBuiltInIds`, seeded through the `catalog-settings` TransferState with the counts, so the server HTML and first render match): `shopCategoryMatch` stops opening a deleted Apparel / Accessories / Rackets (it reads `settings/catalog` itself, once and only when a built-in isn't in the published list, because `CatalogService` must not be created before the layout's `catalogSettingsResolver` seeds it on the server), and the built-in menu (`NavService.builtInCategories`, used when nothing is saved and by Navigation's reset) and the home defaults (`DEFAULT_HOME_*` through `features/home/utils/home-defaults.utils.ts`: hero buttons dropped, a shop card opens Shop All, category-list rows dropped) leave out links to them (`pathOpensDeletedBuiltIn()` in `core/services/products/utils/deleted-built-ins.ts`). A saved home page or menu is shown as saved.
- A new category or brand never takes the id of a deleted built-in or any id an offer names (`offerCatalogIds()`; it gets `-2` instead), so an old offer never starts covering a new category or brand; a full `recountCatalog` writes no count key for deleted built-ins, and Check catalogue structure never sets `brandId` to a deleted built-in from a product's old `brand` text.
- The delete check counts products with two `count()` queries (all, and `published == true`), never by reading them.
- A new category or brand whose name has no English letter or digit (only Arabic, say) is refused in the Add window and by `saveCategory` / `saveBrand`: "Use English letters for the name, for example Padel Caps." (renaming a saved one is not affected).
- **Add to the Menu (<KEY>-248)**: Add Category and Add Brand have an optional menu section (`app-menu-placement`, `catalog-manager/components/menu-placement/`; new items only; when it starts on is below): Menu (a top menu with columns from `settings/navigation`, `NavService.categories()`) and Column (columns set to Fill Automatically are left out, with a note that new items appear there by themselves).
- Since <KEY>-264 the switch names the menu that opens the chosen **Inside** category (`menuForCategory()`: its target is that category, or its path is the category's address) or, for a brand, the Brands page (`menuForBrands()`), as "Show in the Apparel menu" (`menuDisplayName()` turns "APPAREL" into "Apparel"); then it starts on and asks only for the Column (a new brand starts off when a column already fills itself with brands, so it never shows twice). With no such menu it reads "Show in a menu", starts off and asks for Menu and Column.
- After the callable creates the category or brand, the dialog adds `{ label: name, path, target: { kind: 'category' | 'brand', id }, isBrand? }` at the end of that column through `CatalogAdminService.addToMenu()` (pure `addLinkToMenu()` in `catalog-manager/utils/menu-placement.utils.ts`, then `NavService.updateNavigation()`, the save Navigation uses).
- A failed or timed-out menu step keeps the category or brand and the tab shows "Saved the category, but the menu didn't confirm the new link. Check Navigation and add it there only if it's missing." (the dialog closes with `menuFailed`).
- `addLinkToMenu()` adds nothing when the column already has a link to that category or brand, so a slow save that lands after its 15-second timeout plus a retry never makes a duplicate.
- A new sub-category whose parent has a Fill Automatically "Sub-categories of <parent>" column shows "It will appear in the <menu> menu by itself." and the section is switched off (`menuFillingSubCategories()`).
- Drag the handle to reorder within one level (top-level categories, one parent's sub-categories, or brands); `reorderCatalog` writes `sortOrder` 10, 20, 30… and refuses ids from two levels.
- After an add, show / hide or rename, the callable refreshes `settings/catalog` for that id (scoped `recountCatalog`); a delete removes its key from `settings/catalog` with a field path.
- After a rename, the callable re-sends that category's or brand's published products to Algolia with a fresh `getCatalogLookup(db, true)`.
- An add, rename or delete stamps `settings/catalog.namesChangedAtMs`; `getCatalogLookup()` reads that stamp on each cache hit and rebuilds when it changed, so no warm function instance sends an old name to search.
- The page shows a category's address as `/category/<path>` (`/category/apparel/caps` for a sub-category), the canonical address the store and sitemap use.
- Shop's Brand filter matches by name, so renaming a brand stops old `/shop?brand=<Old Name>` links from matching; the brand dialog says so and staff update those links in Navigation and Home Page.
- Hide takes a category or brand out of the menus and lists; built-in category pages and Shop routes still open by their address (not once staff deleted them).
- The product editor's Category and Brand pickers list hidden ones too, marked "(hidden)", so staff can fill a category before showing it.
- A category or brand added there gets the size chart and Materials / Specifications title from its own **Size Chart** and **Details Title** (or its parent's, <KEY>-250); a sub-category gets the normal `/category/<path>` page and a brand `/brand/<slug>`.
